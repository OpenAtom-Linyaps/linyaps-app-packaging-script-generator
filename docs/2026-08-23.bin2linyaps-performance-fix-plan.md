## Phase A — 专用约束 SKILL + agent 调用优化（最大 token 收益）

### A1 新建 `skills/bin2linyaps.constraints/SKILL.md`

```yaml
---
name: bin2linyaps.constraints
description: 【linyaps-app-packaging-script-generator】通用构建约束的唯一权威。承载本 workflow 全部 skills 共享的构建/校验约束，由 agent 在初始化阶段一次性载入，各子 skill 引用本 SKILL 而非各自复述。
user-invocable: false
---
```

内容要点（精炼，非散文）：
- **wrapper/command 契约**：`command` 与 desktop `Exec` 由 `pak_linyaps.sh` 构建时 wrapper 机制自动设置；禁止手动填充 command；禁止 envsubst 阶段导出 `command`。
- **version 契约**：`version` / `package.version` 必须保持 `${ll_version}` 变量；由 `convert_version_to_linglong()` 归一化，禁止绝对化。
- **package_id 契约**：工程 `CI_ll_<package_id>` 命名、反向域名格式、`ll_id` 非空。
- **base/runtime 契约**：组合必须通过 `config/base_runtime_whitelist.conf` 白名单。
- **依赖存在性核验**：`buildext.apt.depends` 写入前逐包 `apt-cache show` 核验（`scripts/depends.py`）。
- **模板完整性**：`pak_linyaps.sh` 必须完整复制模板，不得简化脚本调用。

### A2 agent 侧调用优化（关键：高效启用）

1. 标准 agent `agents/deb-linglong-packer.agent.md` **Phase 1 初始化末尾**增加：
   ```
   skill({ name: "bin2linyaps.constraints" })   # 一次性载入约束契约
   ```
2. 各 `bin2linyaps.*` SKILL 的整段约束叙述 → 一行引用：
   ```
   > 遵循 bin2linyaps.constraints SKILL：wrapper/command 契约、${ll_version} 版本契约、template 完整性（详见该 SKILL）。
   ```
3. **大幅精简 `skills/bin2linyaps.deb.project-gen/SKILL.md`（1237 → 目标 300-400 行）**：删除重复的「错误示例 vs 正确示例」「生成后自检清单」「常见错误警告」重复段，保留单份权威。
4. 精简 `collect-resources`、`tar.transfer`、`appimage.transfer`、`fix` 的重复 wrapper 叙述。

### A3 命名歧义收敛（沿用参考增补方案）

- 子 SKILL 中引用统一为「`bin2linyaps.constraints` **SKILL**」自标识（比裸名 +1~2 token）；
- 纯冗余的「遵循 `bin2linyaps.constraints`（…）」复述**直接删除**（其内容实为父 agent 已一次性载入，或本技能 description/脚本行为）；
- 加载方式/fallback 只存在于两个父 agent 与 `bin2linyaps.constraints` SKILL 自身。

**落地文件**：
- 新建 `skills/bin2linyaps.constraints/SKILL.md`
- 精简 `skills/bin2linyaps.deb.project-gen/SKILL.md`、`collect-resources/SKILL.md`、`tar.transfer/SKILL.md`、`appimage.transfer/SKILL.md`、`fix/SKILL.md` 的重复约束段

> ⚠️ 权衡：multica 复制模型下 `bin2linyaps.constraints` 独立下发，其他 skill 通过 `skill()` 按 name 运行时引用（非跨目录文件 import）。若某环境未下发该 skill，agent 需最小内联 fallback（执行时确认）。
